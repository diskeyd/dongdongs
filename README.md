# dongdongs — 시험성적서 PDF를 한글 보고서에 옮겨 주는 프로그램

시험기관이 보낸 성적서 PDF 한 개를 읽어서,

1. PDF에 찍힌 **DRAFT 도장을 지우고** (쪽 번호·문서 코드는 그대로 둡니다),
2. 표의 값과 그래프·회로도 그림을 **꺼낸 다음**,
3. 브라우저 검수 화면에서 **사람이 승인한 것만** 기존 한글 보고서의 **사본**에 넣습니다.

원본 PDF와 원본 HWP는 절대 바뀌지 않습니다. 결과는 항상 새 파일로 나옵니다.

보고서 한 권은 **여러 성적서로 채웁니다.** 시험 항목(구역)마다 성적서가 다르고, 성적서는 한꺼번에 오지 않습니다. 그래서 **성적서가 올 때마다 한 번씩** 실행하고, 같은 보고서는 이전 결과에 이어서 쌓습니다. 아직 성적서가 없는 구역은 건드리지 않습니다.

> 코드를 고치는 사람은 [`docs/개발.md`](docs/개발.md)를 보세요. 이 문서는 프로그램을 **쓰는** 사람을 위한 안내입니다.

## 3단계. 설치

폴더 안의 **`install.bat`을 더블클릭**합니다. 검은 창이 열리고 필요한 것을 알아서 내려받습니다(처음 한 번 몇 분).

"설치가 끝났습니다"가 나오면 완료입니다. 창에 오류가 보이면 그 창을 닫지 말고 [처음 쓸 때 — 순서와 보내 줄 것](#처음-쓸-때--순서와-보내-줄-것)로 가세요. 창이 그냥 사라져 버리면 아래 [자주 묻는 것](#자주-묻는-것)을 보세요.

폴더 안에 이런 것이 생깁니다.

| 폴더/파일 | 용도 |
|---|---|
| `input\` | 성적서 PDF와 보고서 HWP를 여기에 두면 찾기 편합니다 (다른 곳에 있어도 됩니다) |
| `work\` | 작업 결과가 작업 이름별로 쌓이는 곳 |
| `reports\` | 오류 보고 zip이 생기는 곳 |
| `logs\` | 실행 기록 (오류 보고 zip에 들어갑니다) |
| `dongdongs.env` | 설정 파일 (Gemini 키를 여기에 넣습니다) |

> 참고: `install.bat`은 [uv](https://docs.astral.sh/uv/getting-started/installation/)라는 실행 도구를 씁니다. 몰라도 됩니다.

## 3-1단계. 한글 연결 확인 (설치 후 한 번)

**`doctor.bat`을 더블클릭**하면 이 PC 가 한글에 값을 넣을 수 있는지 알려 줍니다. 마지막 줄의 판정만 보면 됩니다.

| 판정 | 뜻 |
|---|---|
| `한글 COM 을 쓸 수 있습니다` | 그대로 5단계로 |
| `한글은 32비트이고 이 프로그램은 64비트라서…` | 아직 반영이 안 됩니다. 이 화면을 Issue 에 올려 주세요 |
| `COM 자동화가 등록되어 있지 않습니다` | 한글을 한 번 직접 실행해 본 뒤 다시 눌러 보고, 그래도 같으면 Issue 에 올려 주세요 |
| `한글(한컴오피스)을 찾지 못했습니다` | 한글이 설치된 PC 에서 실행해야 합니다 |

등록이 안 돼 있으면 `doctor.bat` 이 **"지금 등록할까요?"** 라고 묻습니다. `y` 를 누르고 Enter → 관리자 권한 창이 뜨면 **[예]** → 다시 판정을 보여 줍니다. 대부분 이걸로 해결됩니다(`run.bat` 도 같은 질문을 합니다).

이 화면에는 성적서·보고서 내용이 들어가지 않으니 그대로 복사해 올리셔도 됩니다. 반영이 안 되는 PC 라도 분석과 검수까지는 할 수 있습니다. `install.bat` 이 끝날 때도 같은 진단을 한 번 보여 줍니다.

## 5단계. 실행하기

성적서 **한 개마다 한 번** 실행합니다.

1. **`run.bat`을 더블클릭**합니다.
2. 검은 창이 묻는 대로 답합니다.
   - `1) 시험성적서 PDF 파일` → 탐색기에서 PDF 파일을 **검은 창 안으로 끌어다 놓고** Enter.
   - `이 보고서의 이전 결과에 이어서 넣을까요?` → 같은 보고서에 전에 다른 성적서를 넣었다면 이 질문이 나옵니다. 이어서 넣으려면 **그냥 Enter**, 다른 보고서면 `n`. 작업 중인 보고서가 여러 개면 목록이 나오고 **번호**를 고릅니다(새 보고서면 그냥 Enter).
   - `2) 보고서 HWP 파일` → 이어서 넣지 않을 때만 나옵니다. HWP 파일을 끌어다 놓고 Enter. **처음 넣는 보고서는 원본 HWP**를 넣습니다.
   - `3) 작업 이름` → 그냥 Enter (오늘 날짜·시각으로 정해집니다).
3. 분석이 자동으로 돌아갑니다. 몇 분 걸립니다. (DRAFT 삭제 → 삭제 검증 → 표·그래프 추출 → HWP 조사 → 후보 만들기)
4. **어느 구역에 넣을지 확인**합니다.
   - 성적서의 시험 목록을 읽었으면 `이 성적서를 넣을 보고서 구역:` 아래에 `2. ○○시험(코드) ← 성적서 '○○시험 (코드)'`처럼 짝을 보여 줍니다. 맞으면 Enter.
   - 틀렸으면 `n`. 보고서 구역 목록과 성적서 시험 목록이 나옵니다. **성적서 시험 순서대로 구역 번호를 하나씩** 적습니다(예: `2,3,0` — 넣지 않을 시험은 `0`).
   - 성적서에 시험 목록이 없으면 바로 구역 목록이 나옵니다. 이 성적서가 채울 번호를 `2,3` 또는 `10-12`처럼 적습니다.
   - 번호 없이 Enter만 누르면 넘어가지 않습니다(구역을 모른 채 넣으면 그래프가 엉뚱한 구역에 들어갑니다). 그만두려면 `q`.
5. 브라우저에 **검수 화면**이 열립니다. 아래 "검수 화면 보는 법"대로 승인하고 **[저장]**을 누릅니다.
6. 검은 창으로 돌아와 **Enter**를 누르면 "반영할까요?"라고 묻습니다. `y` → Enter.
7. 한글이 **화면에 보이지 않게** 열려서 승인한 값과 그림을 넣습니다. 이 창을 최소화하고 다른 일을 하셔도 됩니다. 다만 끝날 때까지 **한글로 다른 문서를 편집하지 마세요**. (한글이 하는 일을 눈으로 보고 싶으면 `dongdongs.env` 에 `HWP_VISIBLE=1` 을 넣으세요.)
8. 끝나면 결과 파일 위치와 **보고서 현황**이 나옵니다. 예) `구역 12개 중 반영 3 · 일부 1 · 차단 1 · 대기 7`

### 성적서가 여러 개일 때 — 보고서 한 권 채우기

| 언제 | 할 일 | 결과 |
|---|---|---|
| 첫 성적서가 왔을 때 | `run.bat` → PDF → **원본 HWP** | 그 성적서의 구역만 채운 `보고서이름.processed.hwp`. 나머지 구역은 그대로 |
| 기다리는 동안 | 할 일 없음 | 결과는 `work\작업이름\result\`에 남습니다. **옮기거나 한글에서 고치지 마세요** |
| 다음 성적서가 왔을 때 | `run.bat` → PDF → "이어서 넣을까요?"에 Enter | 이전 결과에 새 구역이 더해진 파일 |
| 성적서를 다 넣었을 때 | 마지막 작업의 `…processed.hwp`가 완성본 | 현황이 `대기 0` |

- 현황의 뜻: **반영** = 그 구역을 다 넣음 · **일부** = 보류했거나 반영에 실패한 항목이 남음(같은 성적서로 다시 실행) · **차단** = 넣을 수 없는 항목이 있음(아래 `blocked` 이유 참고) · **대기** = 아직 성적서가 없음.
- 이미 넣은 성적서를 다시 넣으면 표 값과 그래프 쪽은 대부분 "변경 없음"으로 나옵니다. 회로도는 같은 그림이라도 다시 교체 후보로 나오니 거절하면 됩니다. 값이 고쳐진 성적서가 다시 왔을 때 쓰면 됩니다.
- 이전 결과 파일을 옮기거나 한글에서 직접 고치면 "이어서 넣을까요?"가 나오지 않습니다(파일이 바뀐 것을 알아챕니다). 그때는 그 파일을 `2) 보고서 HWP 파일`에 직접 끌어다 놓으세요.
- 마지막에 "HWP 검증 실패"가 나온 결과로는 이어 쓰지 않습니다. 현황도 갱신되지 않습니다.

### 검수 화면 보는 법

화면 맨 위 **보고서 구역** 칸에 이 성적서가 채우는 구역, 이전에 이미 반영된 구역, 성적서가 아직 없는 구역이 나옵니다. 아래 표도 구역별로 묶여 있습니다. 표 한 줄이 "바꿀 것 하나"입니다.

| 열 | 뜻 |
|---|---|
| 근거 | 성적서 PDF에서 잘라낸 원본 조각. 이걸 보고 판단합니다 |
| HWP 위치 | 한글 보고서의 몇 번 표, 어느 칸(또는 몇 쪽)인지 |
| HWP 현재값 | 지금 한글에 적혀 있는 값 |
| 추출값 | PDF에서 읽은 값 |
| 반영값 | 한글에 실제로 들어갈 값. **직접 고칠 수 있습니다** |
| 표시 | 주의할 점. 노란색이면 한 번 더 보세요 |
| 결정 | 승인 / 거절 / 보류 |

- 이미 같은 값인 줄은 **회색 바탕 + `변경 없음` 표시**로 나옵니다(항목 이름·단위 칸이 대부분 여기 해당). **[변경 없음 항목 모두 승인]** 버튼으로 한 번에 승인하면 되고, 이 줄만 승인하면 한글에 넣을 것이 없습니다.
- 화면 아래 **[값이 바뀌는 줄만 보기]** 를 켜면 실제로 바뀌는 줄만 남습니다. 1회차에는 여기서 하나만 골라 승인하세요.
- **회로도**는 한글에 있던 그림 자리의 **가로 폭을 그대로 쓰고 세로만** 맞춥니다(보고서 모양이 밀리지 않게). 성적서 그림이 그 자리보다 세로로 길면 세로가 눌리고 `picture_height_squeezed` 로 표시됩니다.
- **그래프 쪽** 줄에는 그래프 미리보기와 "배율 84%" 같은 숫자가 보입니다. 성적서 그래프의 가로세로 비율은 그대로 두고, 한글 한 쪽에 들어가도록 전체를 그만큼 줄였다는 뜻입니다.
- 한글에 그래프 쪽이 모자라면 "(추가)"라고 표시됩니다. **그 구역의** 마지막 그래프 쪽을 복사해 바로 뒤에 새 쪽을 만듭니다.
- 빨간 `blocked` 표시가 있는 줄은 승인할 수 없습니다. 이유는 옆 표시로 구분합니다.
  - `watermark…` — 그 쪽의 DRAFT를 자동으로 지우지 못했습니다. 아래 "보내는 방법"대로 알려 주세요. 나머지 쪽은 정상 처리됩니다.
  - `no_graph_page_in_section` — 보고서의 그 구역에 그래프 쪽(`Osc.` 쪽)이 하나도 없어 복사할 쪽이 없습니다. 한글에서 다른 구역의 `Osc.` 쪽 하나를 그 구역 끝에 복사해 넣고 저장한 뒤 같은 성적서로 다시 실행하세요. 이때:
    - 복사한 쪽의 `Osc. …` 제목 줄 끝에 **구역 번호**를 붙여 다른 쪽과 제목이 겹치지 않게 합니다(예: 9번 구역이면 `-9`).
    - 복사한 쪽의 머리 칸(성적서 번호 등)은 원래 구역 것이 따라오니 그 구역에 맞게 고칩니다.
    - 다시 실행할 때 "이어서 넣을까요?"에는 `n`을 누르고, 고쳐 저장한 파일을 `2) 보고서 HWP 파일`에 넣습니다.
  - `anchor_text_not_unique` — 보고서에 같은 `Osc.` 제목이 두 번 이상 있어 어느 쪽인지 구별할 수 없습니다. 한글에서 제목이 겹치지 않게 고치고 다시 실행하세요.
  - `cell_has_other_text` — 그래프 쪽에 제목 말고 다른 글이 있어 채우면 지워집니다. 그 쪽은 한글에서 직접 넣어 주세요.
- 저장은 여러 번 해도 됩니다. 나중에 다시 열면 이어서 볼 수 있습니다.

### 결과 확인

`work\작업이름\result\` 폴더에 두 파일이 생깁니다.

| 파일 | 뜻 |
|---|---|
| `보고서이름.processed.hwp` | **결과**. 이 파일을 한글로 열어 확인합니다 |
| `보고서이름.before.hwp` | 반영 전 사본. 비교용 |

이어서 넣어도 이름은 계속 `보고서이름.processed.hwp`입니다(작업 폴더마다 하나). 가장 최근 작업의 파일이 최신입니다.

검은 창 마지막에 "HWP 검증 통과"가 나오면 표 구조와 그림 수가 계획대로인 것입니다. "실패"가 나오면 결과 파일을 쓰지 말고 [처음 쓸 때 — 순서와 보내 줄 것](#처음-쓸-때--순서와-보내-줄-것)로 가세요.

## 고급: 명령으로 단계별 실행

`run.bat` 대신 검은 창에서 직접 실행할 수도 있습니다. 폴더에서 `Shift + 오른쪽 클릭` → "여기에 PowerShell 창 열기".

```powershell
uv run dongdongs init --pdf ".\input\성적서.pdf" --hwp ".\input\보고서.hwp" --work-dir .\work --job-id 작업이름
uv run dongdongs analyze --job .\work\작업이름
uv run dongdongs review  --job .\work\작업이름
uv run dongdongs apply   --job .\work\작업이름 --visible
uv run dongdongs verify  --job .\work\작업이름 --stage hwp
uv run dongdongs report  --job .\work\작업이름

# 이 성적서가 채울 보고서 구역을 직접 지정
#   성적서에 시험 목록이 있으면 시험 순서대로 하나씩 (0 = 넣지 않음): --sections 2,3,0
#   목록이 없으면 채울 구역 번호들: --sections 2,10-12
uv run dongdongs map --job .\work\작업이름 --sections 2,3,0

# 이전 작업 결과에 이어서
uv run dongdongs init --pdf ".\input\다음성적서.pdf" --hwp ".\work\이전작업\result\보고서.processed.hwp" --parent-job 이전작업 --work-dir .\work --job-id 새작업
```

단계별 명령(`inspect-pdf`, `clean`, `extract`, `inspect-hwp`, `map`)과 옵션은 `uv run dongdongs --help`에 있습니다.
