# dongdongs 개발 문서

사용법은 저장소 루트의 `README.md`(비개발자용)에 있다. 이 문서는 코드를 고치는 사람을 위한 것이다.

## 현재 상태

| 단계 | 명령 | 상태 |
|---|---|---|
| 환경 기록 | `init` | 동작 확인 (macOS) |
| PDF 객체 조사 | `inspect-pdf` | 동작 확인 |
| 워터마크 객체 삭제 + 무변형 검증 | `clean`, `verify --stage clean` | 실제 성적서 전 쪽 통과 (150·300 DPI, 테두리 밖 픽셀 차이 0) |
| 표 값 추출 | `extract` | 동작 확인 |
| 그래프·회로도 PNG | `extract` | 동작 확인 (300 DPI). 한 쪽에 가로 1장 + 반폭 2장이 있는 배치도 3장으로 뽑는다 |
| HWP 구조 조사 | `inspect-hwp` | 동작 확인 (읽기 전용, OS 무관). 쪽 번호·그래프 쪽 탐지 포함 |
| 시험 구역 지도 | `extract`(sections.json), `inspect-hwp` | 동작 확인. PDF 시험 목록 쪽 → 시험별 쪽 범위, HWP `N. 이름(코드)` 제목 → 구역별 쪽 범위 |

| 검수 화면 | `review` | 127.0.0.1 로컬 서버 |
| HWP 반영 | `apply` | **아직 한 번도 반영되지 않음.** 2026-09-17 사용자 PC: `import pyhwpx` 가 `TYPE_E_LIBNOTREGISTERED` 로 중단 → 원인은 한컴오피스 2022(32비트, 일반 설치본)에 자동화 등록이 빠진 것. `Hwp.exe /regserver`(관리자) 한 줄로 해결(이제 `doctor` 가 대신 실행해 준다). **2026-09-17 1회차 통과**: 표 셀 1개 `applied`, 저장됨, `verify --stage hwp` 통과, 보안 모듈 자체 등록 `ok`. 회로도·그래프 쪽·쪽 추가는 아직 |

```text

├─ support.py        dongdongs.env 로딩, 실행 로그, 오류 보고 zip(비식별)

├─ job.py            work/<job>/ 레이아웃, manifest.json, report_stem()
├─ ledger.py         보고서 장부 work/_reports/<보고서명>.json (구역별 반영 현황, 최신 결과)
├─ config/
│  ├─ institutions.yaml  기관 규칙(워터마크, 푸터 레이어, 표 구역, 그래프 영역, 그림 배치)

├─ pdf/  inspector · watermark · tables · regions · render · sections(시험 목록)
├─ hwp/  inspector(pyhwp XML, 구역 지도) · mapping(구역 짝짓기, 후보) · editor(Windows COM, pyhwpx)
├─ review/  server.py + templates/review.html
├─ gemini.py
└─ verify.py         PDF 무변형 오라클, HWP 반영 전후 비교
```

## 보고서와 성적서의 구역

보고서 한 권은 시험 항목 구역 여러 개로 되어 있고, 구역마다 다른 성적서(기관이 다를 수 있음)에서 온다. 구역 수·이름은 보고서마다 다르므로 코드에 박지 않고 문서에서 읽는다. 샘플 보고서의 수치는 `tests/local/expected.json`에만 있다.

| 문서 | 읽는 법 | 설정 |
|---|---|---|
| HWP | 최상위 쪽 틀 표 셀의 첫 줄이 `N. 이름(코드)`인 쪽이 구역 시작(`inspector.report_sections`). 번호가 **가장 길게 증가하는 줄**만 인정(같으면 번호 틈이 적고 앞선 것) — 표지·목차의 번호 줄이나 구역 안 번호 메모는 빠지고, 빠진 줄과 건너뛴 번호는 경고로 남는다. 점 뒤 공백 필수(`25.8kV`는 제목 아님). 코드는 괄호 안이 영문일 때만(`(일반)`은 코드 아님) | `institutions.yaml` `report:` |
| PDF | 기관 규칙 `sections.index_title`이 있는 쪽에서 `이름(코드)`와 시작 쪽을 읽는다(`pdf/sections.read_test_index`). 끝 = 다음 시험 시작 − 1, 마지막 = 목차의 `end_titles` 쪽 − 1 | `institutions.<기관>.sections` |

짝짓기(`mapping.resolve_scopes`):

- `auto` — PDF 시험과 HWP 구역을 코드로, 없으면 이름(공백 무시)으로 짝짓는다.
- `user` — `--sections`로 사람이 고른 구역. PDF 시험 목록이 있으면 **시험 순서대로 구역 번호 하나씩**(`0` = 그 시험은 넣지 않음). 개수가 다르거나 없는 번호·중복이 있으면 후보를 만들지 않는다(예전처럼 PDF 전체를 고른 구역에 붙이면 모든 그래프가 한 구역 뒤로 복사된다). 목록이 없으면 고른 구역들을 한 범위로 묶어 PDF 전체와 짝짓는다.
- `whole` — 구역 정보가 없을 때 문서 전체 대 전체. 이때는 어느 구역도 "손대지 않음"이라 할 수 없어 `pending_sections`가 비어 있다. 보고서에 구역이 있으면 마법사(`wizard.confirm_sections`)가 빈 답을 받지 않고 구역 번호를 받을 때까지 묻는다.

`build_candidates`는 짝마다 PDF 쪽 범위·HWP 쪽 범위 안에서만 표·회로도·그래프 쪽·오실로그램 칸을 짝짓고 후보에 `section`을 붙인다. 성적서가 없는 HWP 구역은 `pending_sections`로만 남는다.

그래프 쪽:

- 모자란 쪽은 **그 구역의 마지막 그래프 쪽 바로 뒤**에 복사한다(앵커 = 그 쪽 제목, `hwp.anchor_page`). `editor.apply_changes`는 앵커 제목별로 묶어, 묶음의 첫 추가 쪽에서 승인된 추가 쪽 수만큼 복사하고 앵커 쪽을 고치기 전에 복사본부터 채운다.
- 앞 구역에 쪽이 들어가면 뒤 구역 쪽 번호가 밀린다. 후보는 `page_no_before`(입력 문서)와 `page_no_after`(모두 승인했을 때)를 가진다. `verify`는 `apply_log.json`의 `copies`로 다시 계산한다(`mapping.graph_page_positions`).
- 구역에 그래프 쪽이 하나도 없으면 다른 구역 그래프 쪽을 크기 본으로 계획만 하고 `blocked` + `no_graph_page_in_section`. 사용자가 한글에서 그 구역 끝에 `Osc.` 쪽 하나를 넣고 다시 실행한다(README: 제목 끝에 구역 번호, 머리 칸은 손으로 고침).
- 반영기는 앵커를 제목 문자열의 "몇 번째 등장"(`occurrence_of`)으로 찾고 복사 묶음도 제목으로 묶는다. 그래서 그래프 쪽 두 개가 같은 제목이면(씨앗 쪽 제목을 안 바꾼 경우 등) 그 제목의 쪽 후보를 `anchor_text_not_unique`로 막는다(`Osc. 1`과 `Osc. 10`처럼 한쪽이 다른 쪽을 포함하는 것은 겹침이 아니다). 큰 셀에 제목 말고 다른 줄이 있으면 채울 때 지워지므로 `cell_has_other_text`로 막는다.
- 그래프가 들어갈 폭은 큰 셀 폭 − `padding_width_mm`(보고서 양식마다 셀 폭이 달라도 맞는다).
- 제목과 그림 수가 이미 같으면 `no_op`(같은 성적서를 다시 넣은 경우).

## 보고서 장부와 이어 쓰기

`verify --stage hwp`가 통과하면 `ledger.update_ledger`가 `work/_reports/<보고서명>.json`을 갱신한다: 구역별 `done`(모든 후보가 결정되고 승인분이 다 들어감) · `partial`(보류·미결정 항목이나 반영 실패가 남음) · `blocked`(나머지는 됐지만 차단 후보가 있음) · `pending`(성적서 없음). 반영된 것이 하나도 없는 구역은 바꾸지 않는다. 그리고 최신 결과 파일(작업 폴더 기준 상대 경로 + sha256), 작업 이력. 마법사는 결과 파일이 그대로면(sha256 일치) "이어서 넣을까요?"를 묻고 `init --hwp <이전 결과> --parent-job <이전 작업>`으로 시작한다. 결과 파일 이름은 `job.report_stem`이 `.processed`·`.before`를 떼어 항상 `<보고서명>.processed.hwp`다. 장부에는 값이 없고 보고 zip에도 들어가지 않는다.

## 후보의 세 가지 종류

| kind | 무엇을 | 반영 방법 (editor.py) |
|---|---|---|
| `set_cell_text` | 표 셀 텍스트 | 앵커 머리 셀 → 셀 이동 → 현재값 확인 → 삭제 후 InsertText → 읽어서 확인 |
| `replace_picture` | 회로도 그림 | 셀 안 그림 컨트롤 크기 확인 → DeleteCtrl → InsertPicture(sizeoption=1, mm) → Properties 로 hwpunit 재설정 → 크기 ±1 % 확인 |
| `fill_oscillogram_page` | 그래프 쪽 | 큰 셀의 제목 줄 교체 → 그래프를 PDF 배치 그대로 삽입(가로 1장 한 줄, 반폭 2장 한 줄, 글자처럼 취급, 가운데 정렬) → 그림 수 확인. HWP 쪽이 모자라면 그 구역의 마지막 그래프 쪽 틀 표를 바로 뒤에 복사해 추가 |
| `replace_picture` (오실로그램 칸) | `오실로그램` 머리 셀이 있는 표의 그림 칸 | 그래프 쪽이 가져가지 않은 오실로그램을 문서 순서대로 칸에 짝지어 회로도와 같은 방법으로 교체. **아직 이런 표가 있는 성적서를 본 적이 없어 짝짓기 규칙은 미확정**(`slot_paired_by_order` 표시) |

그림 크기 정책(2026-09-13 결정): **성적서 비율을 그대로 유지하고, 들어갈 상자(셀 안쪽 또는 기존 그림 크기)에 맞는 가장 큰 배율 하나로 줄인다.** 그래프 쪽은 쪽 전체에 배율 하나(`hwp.page_scale`)를 써서 PDF 배치가 그대로 유지되고, 그림은 가운데 정렬로 넣는다. `fit_picture`가 `scale`·`fill_ratio`를 기록하고, 상자의 절반도 못 채우면 `picture_small_in_box`로 표시한다. 그래프 쪽의 사용 가능 높이 = 큰 셀 높이 − 안여백 − 제목·빈 줄(`institutions.yaml` `pictures.oscillogram_page`). 회로도는 기존 그림 상자 크기(보고서마다 다름)에 비율을 지키며 넣으므로, 상자와 비율이 다르면 한쪽이 빈다.

## 기호 표 (charmap.json)

`src/dongdongs/config/charmap.json`의 `pairs`는 PDF 쪽 글자 → HWP 정본 글자다. `tier`:

| tier | 뜻 | 처리 |
|---|---|---|
| `measured` | 실제 보고서 HWP가 쓰는 코드(Ω U+2126, µ U+00B5 등) | 치환 |
| `standard` | NFKC 로 같은 글자(㎸→kV, 전각→반각, °C→℃) | 치환 |
| `lookalike` | 뜻은 같고 코드가 다른 것(∆→Δ, −→-, ≦→≤) | 치환 + `charmap_lookalike` 표시 |
| `style` | 취향(따옴표, x→×) | 저장만, 적용 안 함 |

`drop_ranges`의 사설 영역 글자(점선 채움용)는 값에서 지우고 `private_glyph_dropped` 표시. 새 쌍을 넣을 때는 `tests/test_charmap.py`가 measured/standard 쌍의 NFKC 동치를 검사한다. 검수 화면에서 `unicode_lookalike_only` 표시가 보이면 표에 없는 새 쌍이니 추가한다.

HWP 본문 설명문에는 비슷하게 생긴 다른 문자(예: 키릴 `І`)로 적힌 기호가 있을 수 있다. 값이 아닌 설명문은 손대지 않는다.

## 코드가 강제하는 안전 규칙

- 워터마크는 규칙의 모든 조건(이미지 크기·해시, 그리는 위치, 반투명 합성, 쪽 비율)이 맞을 때만 **객체 단위로** 지운다. 하나라도 어긋나면 그 쪽은 건드리지 않고 `확인 필요 — 워터마크 수동 처리`로 표시한다. 픽셀은 수정하지 않는다.
- PDF 안에 이름이 "ezPDF Watermark"인 레이어가 있는데 이것은 **쪽 번호·문서코드·주소 푸터**다. DRAFT 도장이 아니므로 지우지 않는다(`protect.ocg_names`).
- 무변형 검증은 원본과 정리본을 렌더링해 비교한다. 워터마크 사각형 밖은 픽셀이 완전히 같아야 하고, 안쪽은 밝아지기만 해야 한다. 푸터와 보호 레이어 객체도 확인한다.
- `extract`는 무변형 검증을 통과한 정리본에서만 실행된다.
- 그래프 PNG는 테두리 전체를 포함하고 제목은 뺀다. 테두리 안쪽은 자르지 않는다. AI 보정은 없다.
- 표 값은 숫자로 바꾸지 않는다(`< 0.1`, `isolated` 그대로). 기호만 `charmap.json`으로 HWP 코드에 맞춘다.
- 모든 후보는 `review_required`로 시작한다. 워터마크 수동 처리 쪽의 그림은 `blocked`라 승인할 수 없다.
- `apply`는 `approved_changes.json`에서 승인된 항목만 반영한다. 원본 HWP를 `before`·`processed` 두 사본으로 복사하고 해시를 확인한 뒤 `processed`만 연다. 결과 사본이 이미 있으면 덮어쓰지 않는다.
- 셀마다 앵커 텍스트와 대상 셀의 현재값이 검수 때 본 값과 같은지 먼저 읽어 확인한다. 다르면 쓰지 않고 건너뛴다. 쓴 뒤 다시 읽어 확인한다.
- 검수 서버는 127.0.0.1에만 바인딩하고 `previews/`, `images/` 밖의 파일은 내주지 않는다.
- 오류 보고 zip(`report`)에는 성적서·보고서·그림·값이 들어가지 않는다. 입력 파일 이름은 `<pdf>`·`<hwp>`로, 로그에 남은 다른 작업의 파일 경로도 `<file.pdf>`처럼 바뀐다. 경고 문장에는 셀 글자를 넣지 않는다(표 번호·행만). `--full`은 값이 포함되므로 공개 Issue에 올리면 안 된다.

## 기관 규칙

`src/dongdongs/config/institutions.yaml`의 `defaults:`에 표 구역 이름·그래프 영역·그림 배치 규칙을 두고, `institutions.<기관>`에는 판별 문자열·워터마크·푸터 레이어·시험 목록 규칙과 기본값과 다른 것만 둔다(`config.with_defaults`, 한 단계 병합). 등록되지 않은 기관의 성적서는 기본값만으로 진행한다: 워터마크는 지우지 않고(DRAFT 도장이 그래프에 남음 — README가 반영하지 말라고 안내), 시험 목록이 없으니 구역은 사람이 고른다. 다른 파일을 쓰려면 `--config`로 지정한다. 새 기관은 `inspect-pdf` 결과(반복 이미지, OCG 사용처)를 보고 규칙을 추가한다. 이름에 "Watermark"가 들어간 레이어라도 본문 요소를 담고 있을 수 있으니 사용처를 확인한 뒤 보호 목록에 넣는다.

## Gemini

`--use-gemini`를 붙였을 때만 호출한다(`start` 마법사는 키가 있으면 자동으로 붙인다). 보내는 것은 잘라낸 PNG와 짧은 지시문뿐이고 전체 쪽은 보내지 않는다. 결과는 후보로만 기록한다. 키는 `dongdongs.env` 또는 환경변수 `GEMINI_API_KEY`로만 읽고 파일·로그에 남기지 않는다. 모델 ID는 `DONGDONGS_GEMINI_MODEL`(기본값은 `gemini.py`).

## 테스트

```bash
uv run pytest                      # 파일 없이 도는 단위 테스트
DONGDONGS_FIXTURE_PDF=/path/성적서.pdf DONGDONGS_FIXTURE_HWP=/path/보고서.hwp uv run pytest   # 실제 파일 테스트
```

`*.bat` 세 개는 **ASCII만** 담은 껍데기이고 같은 이름의 `*.ps1`(UTF-8 + BOM)을 실행한다. 한글이 든 UTF-8 배치 파일을 cmd 가 읽으면 줄 위치를 잘못 잡아 명령을 토막 낸다(2026-09-17 사용자 보고: 한글 조각이 명령으로 실행되고 `install.bat` 창이 바로 닫힘). PowerShell 은 BOM 이 있으면 UTF-8 로 읽고 한글을 콘솔 API 로 출력하므로 코드 페이지와 무관하다. `.gitattributes`의 `-text`로 git 이 줄바꿈을 바꾸지 못하게 막고, `tests/test_batch_files.py`가 ASCII·CRLF·BOM 과 짝이 되는 `.ps1` 존재를 검사한다.

실제 파일 테스트는 PDF·HWP와 기대값 파일(`tests/local/expected.json`, 또는 `DONGDONGS_FIXTURE_EXPECT`)이 있을 때만 실행된다. 성적서, HWP, PNG, 기대값, 요구사항 원문은 모두 로컬에만 둔다(`.gitignore`의 `local/`, `tests/local/`, `work/`). 커밋 전에 고객명·시험번호·실측값이 저장소에 없는지 `git grep`으로 확인한다.

## Windows 첫 실행 체크리스트

`apply`의 COM 호출은 한 번도 실행하지 않았다. 처음에는 반드시:

1. `install.bat` → `run.bat`으로 분석까지 진행하고 검수 화면에서 **표 셀 1개**만 승인해 저장 → 반영 → `.processed.hwp`에서 값 확인 → `verify --stage hwp` 통과.
2. 다음 작업에서 **회로도 1장**만 승인 → 크기(mm)·위치·글자처럼 취급 여부 확인.
3. 다음 작업에서 **그래프 쪽 1개**(기존 쪽)만 승인 → 제목·그림 수·배율·가운데 정렬(`ParagraphShapeAlignCenter`) 확인. 반폭 2장이 한 줄에 놓이는지 본다(줄바꿈되면 `gap_mm`을 키운다).
4. **추가되는 그래프 쪽 1개** 승인 → 그 구역 마지막 그래프 쪽 뒤에 복사본이 생기고 쪽 수가 1 늘었는지 `apply_log.json`의 `page_count_before/after`·`copies`로 확인.
5. 전부 승인 → `verify --stage hwp` 통과 → `work/_reports/`에 장부가 생기고 구역 현황이 맞는지 확인.
6. **이어 쓰기**: `run.bat` → 같은 PDF → "이어서 넣을까요?" Y → 분석이 멈추지 않는지 확인. 한글이 COM으로 저장한 HWP를 pyhwp가 읽는 첫 시험이다(`hwp_inventory.json`의 쪽 수·구역 수가 늘어난 만큼인지). 검수 화면에서 그래프 쪽 대부분이 `no_op`인지 본다.

pyhwpx는 동봉된 `FilePathCheckerModule.dll`을 사용자 레지스트리(`HKCU\Software\HNC\HwpAutomation\Modules`)에 등록한다. 한글 보안 승인 창이 계속 뜨면 pyhwpx 문서의 `register_regedit`를 확인한다.

## 2026-09-17 사고: 반영 0건인데 아무도 몰랐다

사용자 결과 파일이 원본과 sha256까지 같았다. 원인은 `apply` 시작 시 `from pyhwpx import Hwp` 가
`win32.gencache.EnsureModule` 에서 `com_error(-2147319779)` 로 죽은 것. `environment.json` 에는
`com_available: false` 가 **3시간 전 `init` 때 이미** 기록돼 있었다. 드러난 조용한 실패와 조치:

| 문제 | 조치 |

## 아직 안 된 것

- **한글 COM 연결 자체**: 위 사고로 아직 한 번도 열지 못했다. `doctor` 결과에 따라 ⓐ 32비트 파이썬으로 `apply` 만 분리 실행, ⓑ 한글 등록 안내, ⓒ `pyhwpx` import 없이 `win32com.client.Dispatch` 로 늦은 바인딩 중에서 고른다. `find_forward` 를 pyhwpx 의 `FindDlg` 순서에 맞추는 일도 그때 함께.
- **쪽 수 불일치**: 1회차 검증에서 `Hancom counts 193 pages, the inventory 194` 경고. 값 반영에는 영향이 없지만 쪽을 추가하는 4회차 전에 원인을 봐야 한다(pyhwp 의 쪽 나눔 계산과 한글의 실제 쪽 수 차이로 보인다).
- **Windows 실측**: 체크리스트 2~6회차(회로도·그래프 쪽·쪽 추가·전체·이어 쓰기).
- **그래프 쪽 복사(가장 위험)**: `copy_current_frame_after_itself`는 `TableCellBlock`+`TableCellBlockExtend`×2 → `Copy` → 표 밖으로 → `Paste` 순서인데, 한글 버전에 따라 새 표가 아니라 셀 내용만 붙을 수 있다. 실패하면 먼저 pyhwpx의 `select_ctrl(hwp.ParentCtrl)` → `Copy` → 표 뒤로 이동 → `Paste`를 시도한다. 복사는 구역마다 첫 추가 쪽 후보에서 승인된 추가 쪽 수만큼 한 번에 만들고, 이후 각 추가 쪽은 앵커에서 옛 제목을 한 번 검색해 아직 안 채운 복사본을 찾는다(채운 쪽은 제목이 바뀌어 검색에 안 걸린다). `EditorError`면 그 후보만 `error`로 남고 계속 진행하고, 알 수 없는 예외(COM 오류 등)면 거기서 멈추고 나머지를 `skipped_after_error`로 남긴 뒤 저장한다.
- **미확인 COM 동작 두 가지(리뷰 지적, Windows에서 확인)**: ① 복사 루프가 두 번째부터 붙여 넣은 뒤의 캐럿 위치에서 `TableCellBlock`을 실행한다. 캐럿이 표 밖이면 실패할 수 있으니, 그때는 한 번만 `Copy`하고 `Paste`만 N번 하도록 바꾼다. ② `find_forward`는 `RepeatFind`의 `FindType`을 설정하지 않는다. 검색이 안 되면 pyhwpx의 `find()`(FindDlg 기본값 → `FindType` 설정)로 바꾼다.
- **오실로그램 표 칸 채우기**: 샘플 보고서에는 `오실로그램` 표(작은 그래프 여러 장을 담는 칸 모음)가 여러 모양으로 있지만 샘플 성적서에는 대응하는 쪽이 없다. 코드는 그래프 쪽 제목(`^Osc\. `)이 없는 오실로그램을 칸에 순서대로 짝지을 뿐이다. 그런 성적서가 생기면 PDF 쪽 제목·캡션(`Osc.No.01`, `정극성`)으로 짝짓는 규칙을 실측해 넣어야 한다.
- **구역 사이 쪽 복사**: 그래프 쪽이 하나도 없는 구역은 차단만 한다. 다른 구역의 그래프 쪽을 그 구역 끝으로 복사하는 자동화는 체크리스트 4회차가 통과한 뒤에 넣는다.
- **다른 기관 규칙**: KERI 규칙만 있다. 규칙이 없는 기관은 기본값으로 검수까지 가고, 마법사에서 사람이 구역 번호를 고른다. 새 기관 성적서가 오면 그 PDF로 워터마크·`sections:` 규칙을 추가한다. 표를 선으로 그리는 성적서는 표를 못 찾는다(`extract`가 경고).
- **경고 문장 언어**: 후보 생성·검증 경고는 영어이고 검은 창과 검수 화면에 그대로 보인다. 사용 후기에서 어려우면 한국어로 바꾼다.
- **요약 표·목차 쪽 번호**: 보고서 앞쪽의 항목별 판정 요약과 목차 쪽 번호는 갱신하지 않는다(쪽이 추가되면 목차 번호가 어긋난다).
- **행 추가**: PDF에 있는데 HWP 표에 빈 행이 없는 항목은 경고만 남긴다. 표 구조를 바꾸지 않기 위해 행을 늘리지 않으므로 사람이 직접 넣는다.
- **아래·위첨자 서식**: 항목명은 글자로만 쓴다. HWP에서 u<sub>c</sub>의 c를 아래첨자로 만드는 서식 적용은 없다.
- **문서 코드 판독**: 푸터가 벡터라 자동 추출하지 않는다.
- **Circuit components 목록 문장** 교체 후보.
- **HWP 검증 범위**: 표 구조·셀 크기·셀 텍스트·그림 수와 크기만 비교한다. 글꼴·문단 모양 비교는 없다.
